2. How it was tested

Playwright drives Chrome through the app as real users would. The tests live in the repo under e2e/, so they can be rerun any time with npm run e2e.

  • Never the real database. Tests run on a Neon branch, qa-2026-11-13, a copy of production taken today. e2e/env.ts refuses to start if pointed at the production host.
  • A production build on port 3200, not the dev server. The page-update bug below only happens in production builds.
  • Email, file storage and Stripe are off on the test server, so no real email went out. Tests check what the app records about each send instead.
  • Two consultants. A owns the demo clients and is the admin; B owns nothing. Every "B is blocked" check also confirms A can open the same page, so a broken page can't pass as a blocked one.
  • Every page is watched for errors. A test fails on any browser console error, page crash or server error unless that test expects it.

3. Bugs found and fixed

What was wrongWhyFix
Pages didn't update after an action. Save, archive, restore, renew link, exclude a ledger row: the change saved, but the screen showed the old state for up to 50 seconds or until a reload.A React bug in Next 15.5 production builds, triggered by a loading.tsx file (React #35399, Next #86055). Fixed upstream in Next 16.3; no 15.5 patch exists. Dev mode never shows it, which is why it went unnoticed.Removed both consultant loading.tsx files. Every action now shows its result within about a second. Cost: no grey skeleton while a consultant page loads.
Another consultant's client pages answered with status 200 and a "Page not found" screen.Same loading.tsx: the page started streaming before the ownership check ran.Now a real 404, same as a client id that never existed. Tests check the status.
An archived client could only come back through the 8-second Undo toast.No list of archived clients existed anywhere.The dashboard has an "Archived clients" list with Restore.
Sharing a snapshot sent no email, though the button says it sends a link.No share email template existed; only the address was stored.New branded email with the read-only link. The timeline records whether it sent.
Correction alerts to people who had the old snapshot left no record, and a failed send vanished.Sends were fire-and-forget.Each recipient gets a timeline entry saying sent or not sent.
The portal's site delegation said "Link sent to your site contact" when no email went out.It reported a send whenever a contact email existed.It says "sent" only when the email went out; otherwise it says to copy the link and share it.
The reports page and the CDP, EcoVadis and Walmart answers left out every uploaded bill. A client whose data came only from uploads showed 0 there while its PDF showed the real total.They summed manual entries only.Both use the same totals as the PDF and snapshots. /for-consultants copy corrected: answers come from current totals, not an approved snapshot.
A snapshot's sha256 couldn't be reproduced from the stored data, so the "proves it never changed" hash couldn't be checked.The hash depended on key order, and Postgres stores keys in its own order.Hashes now use sorted keys. Snapshots frozen before today keep their old hash, as frozen data must.
A utility CSV with a "kWh Used" column imported with no unit and stayed unmapped: no electricity rows, no Scope 2.The unit was only read from a unit column.The unit comes from the header when there is no unit column (kWh, MWh, therms, gallons).
"Request changes" never reached the client. The form says "The supplier is emailed", but no email was sent and the portal didn't show the note.It only changed the upload's status on the consultant side.One branded email to the client per request, and the portal lists each sent-back file with your note.
Flagging an upload left nothing in the activity log.No log call.Logged as "Upload flagged" with the file name.
Approvals were logged as "Upload approved: is_x7k2..." instead of the file name.It logged the internal id.Logs the file name.
"How calculated" said Source "Not recorded" for rows calculated with the built-in factors.It only looked in the factor table, which is empty until real factors are loaded.Falls back to the built-in factor the calculation used (for example "EPA eGRID").
Consultant PDF download failed with a server error on every client.The PDF library loaded React 18 while the app built React 19 elements.React upgraded to 19.2.0 to match Next.
PDF scope tables said "No emissions recorded" under non-zero totals for portal-fed clients.Tables listed manual entries only.Tables come from the same rows as the totals.
PDF methodology claimed "accounting system exports".Left over from the removed QuickBooks import.Removed.

4. Open: needs your decision

Signed-in users get the 404. Fixing it means listing app routes in the middleware instead. A test marks it open (e2e/public.e2e.ts). Keep it, or show a 404?
