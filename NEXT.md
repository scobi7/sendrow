## 🟢 Where the product stands
- **`main` = `sendrow-v3` = `b9036a8`.** Everything below is live on sendrow.app. No branch divergence — every commit this cycle went to `sendrow-v3` then fast-forwarded to `main` same-session.
- **Multi-Office (Plan MO, Phase 1) is deployed to production**, plus follow-ups from live testing: site contact email(s) are now editable at any time (not just before the first send) and support a second recipient (comma-separated); an optional personal note can go out with a site link; site-scoped reminders were fixed to nudge the *site's own* contact instead of the CFO (the cron job was resolving the wrong recipient for `locationId`-scoped requests).
- **Admin panel fixed and expanded.** `/admin/factors` had a redundant second auth check (`ADMIN_EMAIL` + a `userCompanies` lookup) stacked on top of middleware's `ADMIN_CLERK_ID` gate — that double-gate was BUG-1 (the hydration hang). Removed; every `/admin/*` route now relies on the one middleware check, same as `/admin/referrals`. New: **`/admin/accounts`** — grant or revoke free/comped access per consultant account, mirroring what the Stripe webhook does on a real payment. Useful now for onboarding design-test consultants without a working paywall.
- **Broken email links, root-caused and fixed.** Production `NEXT_PUBLIC_APP_URL` was still pointed at `greentrack-sigma.vercel.app` — the pre-rebrand default Vercel domain (GreenTrack → Sendrow; also why every DB table used to carry a `gt_` prefix). Every link in every email 404'd. Fixed the env var (user-side, confirmed) and closed a second latent instance of the same bug class in `app/api/billing/portal/route.ts` (two redirects used `NEXT_PUBLIC_APP_URL!` with no fallback, unlike everywhere else in the codebase).
- **A real cross-tenant data leak found and closed.** `getCommentsForCompany()` checked "is this a consultant" but never "do they own *this* client" — any consultant who knew or guessed another client's ID could read their private line-item Q&A. Fixed with the same `ownsClient()` guard every other action uses.
- **The security contract test (`test/separation.test.ts`) no longer relies on a hand-maintained allowlist.** It protected a fixed list of action/route/page names — 13 exported `consultant-actions.ts` functions and 8 client-detail pages had drifted out of it since it was written (most were actually fine, one wasn't — see above). Rewritten to auto-discover every company-scoped action and every page under `clients/[id]/`, so new code can't silently skip the net again.
- **Evidence downloads no longer redirect to a raw public blob URL.** `/api/evidence/[id]` now streams the file bytes itself, so the real storage URL never reaches the browser. Full private-access storage needs a `@vercel/blob` 1.1.1 → 2.8.0 upgrade (multi-major jump) — out of scope for now, flagged not silently skipped.
- **All 27 database tables renamed off the legacy `gt_` (GreenTrack) prefix** — `gt_companies` → `companies`, etc. Done as a manual `ALTER TABLE ... RENAME` (metadata-only, zero data risk) coordinated with a matching `schema.ts` deploy so there was no window where code and DB disagreed.
- **Dead code from the GreenTrack/pre-pivot era removed**: QuickBooks OAuth routes + `lib/quickbooks.ts`, `lib/utilityapi.ts`, the orphaned `/api/demo` route (zero callers, unrelated to the real `/demo` page), `startUtilityConnectForClient` (redirected to an already-deleted `/connections` page), and the reverted Y1 pipeline board (`components/pipeline-board.tsx` + its now-unused helpers in `lib/client-status.ts`). This closes BUG-6.
- **Marketing/product copy fixed to match reality.** Homepage, `/for-consultants`, and the new-client form all still described clients "connecting their QuickBooks and utility account" for automatic sync — that integration was removed months ago (Plan X4) and copy never caught up. Rewritten everywhere to describe the real flow: a secure link, upload or type it in, no account needed. `/how-it-works` itself was already accurate.
- **Nav decluttered.** Removed "For companies" and "For consultants" from the site nav (both the homepage header and the shared `LandingNav`). `/for-companies` had no other referrers once its own nav link was gone, so the page was deleted outright. `/for-consultants` was kept — five other CTAs point to it, including the homepage's main hero button.
- **BUG-11 (Excel serial dates) fixed.** Files re-saved in Excel/Numbers sometimes turn a date cell into a raw serial number (`45657.66…`). `lib/period.ts` now has `normalizeDateInput()`, which detects this and converts to ISO before it reaches `periodForDate` or gets stored as `activityDate`.
- **BUG-4 (slow queries) audited, one real fix applied.** `loadCompany()` already batches its 7 sub-queries via `Promise.all` and is React-`cache()`-memoized; client detail and review pages already batch theirs too. The manage/scope pages' "auth check, then load" two-step is unavoidable (the guard has to resolve first). Found and fixed one genuine gap: the snapshot page ran a `sites` query sequentially after two other batches despite depending on neither — merged into the existing `Promise.all`.
- **Scope 3 calculation verified real, not placeholder** — traced end to end through the actual code and tests (not just the description). Vendor → category → USEEIO factor → `applyFactor()` → real `co2eKg`, covered by `test/vendor-mappings.test.ts`. Caveat: the factor *values* are labeled "representative" in the source data — correct methodology, not yet the final precise EPA USEEIO/eGRID dataset (same standing blocker as before).
- **Row-level security investigated, shelved for now (not abandoned).** The app's DB driver (`drizzle-orm/neon-http`) has **no transaction support at all** — confirmed empirically, not assumed. RLS needs a session variable set inside a transaction, so it's flat-out impossible on the current driver. The fix (`drizzle-orm/neon-serverless` + `Pool`, WebSocket-based) was tested and confirmed working, but it means swapping the DB driver the *entire app* uses, not just adding policies — a bigger, riskier piece than originally scoped. Decision: hold until there are more consultants on the platform; the app-layer guard (`ownsClient`) plus the now-self-verifying contract test are the safety net in the meantime.
- **Format engine (W3) still not built — now with a concrete example of the cost.** Only 3 buyer questionnaires are supported (CDP, EcoVadis, Walmart Supplier Sustainability), hardcoded as `if (format === ...)` branches in `lib/mapping.ts` — which directly violates the project's own "config, never code" invariant. A client whose buyer is Amazon, Apple, or anyone else gets no mapping help at all today. This is the same blocker as before (needs a real example questionnaire to design against), just now demonstrated with named, concrete buyers instead of an abstract "someday."
- **Theme:** Aurora Green. Tests: **224/224** · tsc + `next build` clean.
