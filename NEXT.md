- **Found and fixed while doing that: the automatic schema push had been silently broken on every deploy for a while, unrelated to Plan L.** `npm run build`'s `drizzle-kit push --force` step was failing every single deploy - it hit a pre-existing pending change (`data_requests.token` had been `.unique()` in `lib/db/schema.ts` for a while but the live table never got that constraint) and tried to show an interactive "do you want to truncate this table?" confirmation, which crashed with "Interactive prompts require a TTY terminal" in Vercel's non-interactive build environment (`--force` is documented to auto-approve exactly this but didn't, in the installed drizzle-kit version). **Practical effect: schema changes had not been auto-applying on deploy for some time**, which is why the two new tables above didn't exist despite several successful-looking production deploys. Checked the live data first (28 rows, zero nulls, zero duplicate tokens), then added the constraint directly (`ALTER TABLE ... ADD CONSTRAINT data_requests_token_unique UNIQUE (token)`). Re-ran the push afterward: clean "Changes applied," no prompt, no crash. **The deploy pipeline's automatic schema push is unblocked going forward** - the next real schema change should apply on deploy without manual intervention.
